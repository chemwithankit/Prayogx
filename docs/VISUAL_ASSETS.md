# Visual assets in experience pages

An **asset-production seam**, not a second media pipeline. It lets an experience page show an approved image,
whether drawn in-house or generated by an external provider, as part of the experience itself. The reel maker
already records the page, so the same image reaches reels and Shorts without being made twice.

```
approved image (tools/visual-assets/, listed in tools/visual_library.json)
   → embedded in the page as data:image/...;base64, drawn on its canvas
   → the experience (self-contained, offline, no fetch)
   → the existing reel maker records the page → reel / Short → the existing gates and publishers
```

## Rules

- **Provenance first.** Every image is listed in `tools/visual_library.json`, the visual twin of
  `tools/reel-maker/audio_library.json`. A record holds `assetId` (`vis-<slug>`), `mediaType`, `source`,
  `generator` (for PrayogX code) or `provider` + `model` + `licenseDocument` (for an external provider), the
  licence fields, `file` and `sha256`. The fields are listed in `tools/visual_assets.py`. Nothing else
  belongs on a record: no concepts, experiences, media IDs or URLs.
- **Licence.** `licenseVerified` and `commercialUse` must be true, and `permittedUse` must include `web`,
  `instagram` and `youtube`, because the page is public and reels record it. An external provider needs a
  licence record in the repository, like `tools/reel-maker/licences/`. **No visual provider is configured.**
  The Higgsfield licence on file covers its voice engine only, so a Higgsfield image needs its own reviewed
  record first.
- **Self-contained.** A page declares `<meta name="px-visual-asset" content="<assetId>">` and embeds the
  approved bytes as a `data:` URI. Its sha256 must match the record, so the page is the approved file. No
  remote URL, no `fetch`, no new file beside `index.html`. The one-file rule (SIMULATION_STANDARDS §2) is
  kept, with no exception.
- **Formats.** PNG, JPEG and WebP up to 2 MB. For motion, the page draws frames (a sprite sheet) on its own
  clock, so the recorder steps it deterministically. **Video is not supported**: the recorder cannot step it,
  and it would need an owner-approved exception to the one-file rule.
- **Enforced** by `tools/check_library.py`, which checks the registry and every page that declares an asset.
  Pages that declare none are unaffected.
- **Generation is separate.** Producing an image (for example with a paid provider) is its own explicit,
  owner-approved step, as for voice. It is never part of building a page or a reel.

Tests: `tests/test_visual_assets.py` (the record, the registry, the page check, shared conventions) and
`tests/visual_asset_capture.js` (the unchanged recorder captures an embedded image; no network at run time).
